# «Освободить место» — первый законченный пользовательский сценарий

**Статус реализации:** код и тесты подготовлены. Результат проверки привязывается к конкретному CI run/SHA; сам этот документ не утверждает успешный Android-прогон.

## Пользовательский путь

1. **Доступ.** Экран объясняет назначение разрешения и реальные границы. Android 11+ открывает системный all-files access; Android 9–10 запрашивает legacy read/write permissions. Возврат в приложение обновляет состояние, но не запускает поиск или удаление автоматически.
2. **Поиск.** Только чтение, с текущей папкой, числом просмотренных файлов и отменой. Root/Shizuku для этого сценария не используются.
3. **Выбор.** Каждый файл или действительно пустая папка — отдельный объект. По умолчанию не выбрано ничего. Счётчик/размер внизу относятся ко всему выбору, даже если поиск или фильтр скрыли часть строк.
4. **Проверка.** Подготавливается конечный список именно выбранных объектов. Объекты, изменившиеся после поиска, исключаются; выбранная пустая папка не раскрывается в новые файлы. Явное согласие на удаление без корзины необходимо для выполнения.
5. **Результат.** Отдельно удалённые файлы/пустые папки, сумма размеров, пропуски и ошибки. Сумма размеров не называется измеренным освобождённым местом. Завершённый итог сохраняется для следующего открытия.

## Что изменилось в интерфейсе

- Вместо пяти технических вкладок — последовательный путь «Доступ → Выбор → Проверка → Результат».
- Названия файлов, размер, раздел и путь; раскрываемая информация с датой и сохраняемым оригиналом.
- Для поддерживаемых изображений, аудио, видео, PDF и текста есть явное открытие внешнего viewer с временным правом чтения одного URI. APK не запускаются, права записи не выдаются.
- Удобное выделение группы доступно только для временных файлов/пустых папок. Личные медиа выбираются пофайлово.
- Поиск/фильтры не меняют выбранное. Повторный поиск сбрасывает старый список и согласие.
- Предупреждение о том, что корзины нет, видно до поиска и перед удалением.
- Известные credential-исключения включены постоянно. В этом сценарии нет переключателя для ослабления защиты.
- Цвет основного действия светлой темы затемнён для читаемых белых подписей.

## Честная область проверки

Первичное общее хранилище: Download, Documents, DCIM, Pictures, Movies, Music, Android/media и общие Telegram/WhatsApp/Viber/VK-папки.

Для каждой области отражается отдельный статус: просмотрено, частично, недоступно, не найдена или не достигнута из-за лимита. Ошибка перечисления не выдаётся за пустую папку.

**Не включены:** Android/data, внутренние данные приложений, другие профили, дополнительные SD-тома и облачные объекты. Нет заявлений об очистке системного кэша или всего телефона. «Остатки удалённых приложений» не определяются по одному отсутствующему package name.

Текущие пределы discovery:

- 10 000 посещённых объектов, 3 000 кандидатов;
- до 6 уровней вложенности и 4 000 элементов одного каталога;
- кооперативный лимит времени 30 секунд;
- поиск точных копий: группы одинакового размера, файл до 64 MiB, суммарное чтение до 256 MiB.

Ограничения становятся частью результата, а не скрытым усечением. Это не жёсткий таймаут зависшего файлового драйвера: отмена проверяется между операциями/буферами.

Совпадение подтверждается SHA-256. Сохраняемый оригинал исключается из **всего** списка кандидатов, а не только из раздела копий. Похожие по картинке кадры не предлагаются как точные дубликаты. Ограничения сравнения видны отдельно.

Личные файлы в списке не считаются мусором. Наличие резервной/облачной копии не проверяется.

## Исполнение и последний итог

Используется прежний finite-file executor: нет рекурсивного удаления дерева после согласия; каждый файл повторно проверяется по снимку и SHA-256. Общая canonical/symlink-граница используется и поиском, и подготовкой, и просмотром.

Новый `requireExactTargets` передаёт в подготовку каталог выбранных leaf-объектов. Чужой путь не расширяет выбор; непустая после поиска папка исключается даже при восстановленном времени изменения.

Перед первой файловой мутацией DataStore подтверждает запись `RUNNING`. Один app-wide mutex охватывает запись начала, исполнение и итог. Ошибка начальной записи не разрешает удаление. Повторное подтверждение не запускает второй проход.

- При завершении сохраняются только счётчики и время, не список личных файлов.
- При отмене/неожиданной ошибке статус неизвестного частичного результата не подменяется нулём.
- После смерти процесса незавершённый marker показывается как неподтверждённый итог. Автоматического продолжения нет.
- Неудачная запись конца явно отмечается в текущем результате; старый `RUNNING` остаётся консервативным предупреждением для следующего запуска.

Это **последний итог**, не полноценная история, не транзакция файловой системы и не способ восстановления. Пропуски с подробными путями доступны для текущего запуска; для актуального состояния нужен новый поиск.

## Проверки

Новые обычные unit-тесты:

- `StorageCleanupScannerTest`: область, границы, ошибки чтения, лимиты, копии, явный выбор, изменения после поиска.
- `CleanupReceiptTest`: запись до удаления, сбой записи, отмена, повторное подтверждение и сериализация параллельных операций.
- `CleanerFlowViewModelTest`: разрешение/возврат, отсутствие автоматического выбора, фильтры, устаревшее согласие, отзыв доступа, отмена/ошибка, незавершённый итог.

Старые 24 файловые safety-теста сохраняются. Чистая файловая логика дополнительно прогоняется вне Android, но это не замена Gradle/JUnit или device-тестам.

Android smoke расширен до **12 случаев: 8 UI + 4 Room**. Для Cleaner на одноразовом API 35 AVD проверяются:

- реальный переход в настройки доступа и возврат без авто-поиска;
- нет выбора по умолчанию, подготовка/отмена/пересоздание Activity;
- удаление ровно одного явно выбранного UUID-scoped fixture при сохранении соседнего;
- пропуск файла, изменённого после подготовки;
- сохранение глобального выбора при смене поиска.

Удаление в тестах разрешено только для созданных тестом синтетических файлов, не для пользовательских данных. Shizuku/Root, физический телефон, production-подпись, визуальная оценка screenshots и реальные backup/cloud-сценарии не входят в эти проверки.

## Известные ограничения

- Корзины и возврата удалённых файлов пока нет. Это отдельный следующий продуктовый/технический шаг, не скрытая гарантия.
- Проверка и unlink не атомарны относительно других приложений.
- Источник сохранённого медиа/назначение `.tmp` остаётся эвристикой; исходное содержимое пользователь проверяет сам.
- Hash выбранного большого файла перед удалением может быть долгим; процесс не изображается мгновенным.
- На Android 9–10 legacy permissions не гарантируют одинаковое покрытие всех OEM/scoped-storage режимов.
- Новый сценарий намеренно уже старого набора «все кэши + трупы + dHash»: неподтверждаемое не выдаётся за законченный безопасный инструмент.

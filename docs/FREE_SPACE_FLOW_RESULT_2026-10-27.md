## Новый пользовательский путь

**Доступ → Поиск → Выбор конкретных файлов → Окончательный план → Результат**

- Вместо технических вкладок — один последовательный сценарий.
- Доступ запрашивается через Android; возврат обновляет UI, не начинает поиск или удаление сам.
- Ничего не выбрано автоматически, включая временные файлы. Внизу всегда виден общий выбор, даже после изменения фильтра/поиска.
- Для каждого объекта видны имя, размер и расположение. Есть подробности и открытие поддерживаемых медиа/документов во внешнем viewer с временным read-only URI. APK не запускаются.
- Показаны реально проверенные, недоступные, отсутствующие и ограниченные папки. Личные файлы не объявляются мусором.
- Точные копии сравниваются по SHA-256 в явно ограниченном бюджете. Сохраняемые оригиналы не попадают в выбор; похожие фотографии не выдаются за дубликаты.
- Подготовка не расширяет выбранную пустую папку в новые файлы. Изменившиеся по снимку объекты исключаются, перед удалением повторно проверяется содержимое.
- Результат различает удаление, пропуски, ошибки и неизвестное прерванное состояние. Последний итог записывается в DataStore, без списка личных файлов.

**Корзины и восстановления файлов пока нет.** Это предупреждение видно до поиска и в окончательном подтверждении. Размер удалённых файлов не выдаётся за измеренный прирост свободного места.

## Исправления по результатам Android-прогонов

Проверка доступа выявила ограничения самого test harness: отзыв all-files access может завершить UID с работающей instrumentation. Теперь состояние «доступ не выдан» устанавливает CI-host **до запуска runner**, а тест проходит настоящий путь Settings → выдача доступа → возврат.

Тест ждёт появления окна Settings перед Back и не отправляет повторные Back по устаревшим accessibility-событиям, которые могли закрыть уже вернувшуюся MainActivity. Ошибки и незавершённые прогоны не маскировались; итоговый прогон целиком зелёный.

В пользовательском потоке дополнительно исправлены сброс прокрутки при смене этапа, подписи счётчиков и защита от перезаписи непарсящегося прошлого итога.

## Что ещё не утверждается

- Проверено API 35 на эмуляторе, не все Android/OEM и не физический телефон.
- Не выполнена визуальная ревизия screenshots, проверка большого шрифта или работа с реально включённым TalkBack.
- Внешние просмотрщики разных форматов требуют проверки на конкретном устройстве.
- Возврат после смерти **всего процесса**, потеря питания и аппаратный сбой DataStore не проверялись Android-тестом; для них реализованы консервативные markers и unit-проверки. Пересоздание Activity не равно смерти процесса.
- До подготовки плана обычные кандидаты фиксируются по metadata, а не полному SHA. Изменение с сохранёнными размером/временем/идентификатором не обязательно различимо на этой стадии. Полный SHA фиксируется при подготовке; перед unlink есть повторная проверка, но это не атомарная файловая транзакция.
- Для новых аппаратных/привилегированных сценариев по-прежнему нужны отдельные проверки.

После этого run добавлены только результат и ссылки в документации (`[skip ci]`). Код/тесты указанного SHA не изменялись. Следующий разумный шаг — визуальная и usability-проверка этого экрана на тестовом телефоне, затем отдельное проектирование корзины/отложенного удаления, если оно требуется продукту.
